# Frontend Stripe test and live flow

Instructors/admins can set an INR course price in create/edit. INR 0 preserves free enrolled access; paid private courses require assignment plus verified server payment, and paid public checkout automatically enrolls after canonical settlement. Existing courses are not repriced. Students see a paywall without lesson content or PDF controls, then use hosted Stripe Checkout in the server-selected **test or live** mode. The paywall shows **Continue to test checkout** with no-real-charge wording for test, or **Continue to payment** with explicit real INR charge wording for live. Return status uses the order's actual mode; create/edit course guidance does not claim a fixed mode. Missing/inconsistent mode responses disable checkout, and a checkout response differing from the displayed quote mode is rejected before redirect. The same active attempt is reused across retries; server-authoritative prices, safe Checkout URLs and pending-state checks prevent double submits or forged redirect success.

Course create/edit has explicit **Free / Paid** radio controls. New courses default to Free; edits derive the choice from the existing price. Free hides the price field and saves `price: 0`, while Paid requires a positive validated INR price. Cards label free courses **Free** and retain **Open course**. A stale paywall whose refreshed quote is free shows **Open course**, without a Stripe configuration warning or Checkout action. Assigned students can read all free materials even when payments are unavailable; private unassigned users stay denied; public free enrollment requires an explicit action. Changing pricing preserves assignments, progress and order history. Returning to Paid rechecks the server's existing purchase status rather than charging verified purchasers again. Stripe failure alone never unlocks a paid course.

All published assigned courses stay visible before payment. Locked cards show the price and Pay to unlock/Review payment action; pending, failed, expired, refund and dispute states come from the server. Verified paid cards unlock, while free courses retain their normal action. Refresh courses reloads these states; refunds/reversals relock the card without removing it. The dashboard only counts unlocked courses as ready to continue.

The return route is `/payments/:orderId`. It reads authenticated server status, polls for up to about one minute and offers an explicit canonical **Check payment status** action. The server must confirm current course access to show **Open course**. Canceled, failed, expired, refunded, disputed and reversed states remain visible; access is rechecked whenever content is requested. There is no artificial course-access expiry yet and no lifetime promise. No voluntary refund UI is included.

No Stripe key is bundled into the frontend. Keep `VITE_API_URL=/api` and existing proxy settings. The backend uses **`STRIPE_MODE=test|live`**, a matching **`STRIPE_SECRET_KEY`** (`sk_test_` / `sk_live_`) and that mode's destination **`STRIPE_WEBHOOK_SECRET`** privately. Live mode requires an exact HTTPS `CLIENT_URL` origin. Mode defaults to test when unset; mismatched keys/events fail closed. No frontend key or mode environment variable is required. Test/live orders and event records use separate backend collections; test payments cannot unlock live content. Private-course assignment remains required in both modes, and switching modes hides the other mode's order pages/grants without deleting records. Deploy both changed repositories; the earlier test-only frontend rejects live responses. The public webhook is the existing backend origin plus `/api/payments/webhook`; it is not a frontend route. The SDK/API contract is stripe 23.0.0 / 2026-09-30.endive. See backend `docs/stripe-test-payments.md` for event subscriptions, configuration, server rules and hosted sandbox verification.

Typography uses installed Segoe UI/Noto Sans/DejaVu Sans system fonts with a 17px root size, slightly larger inputs/buttons/navigation and the existing heading hierarchy. No font service/download or broad visual redesign is introduced. Light/dark/mobile forms and dialogs are checked.

Local checks: `npm run lint`, `npm test`, `npm run build`, `npm run check:cloudflare` (dry-run only). Optional `python3 tests/payments_browser.py` uses installed Python Playwright, Chrome and ffmpeg on a loopback Vite server. API responses and the Stripe page are fixtures; all other external requests are blocked. Set `PLAYER_EVIDENCE_DIR` for screenshots. Existing design/dialog, PDF/course and student player harnesses are also retained. Both test/live flows are checked with local fixtures, including matching labels, wrong-mode redirects, retries, unpaid/paid/refund states and missing/inconsistent configuration. These checks do not verify real hosted Checkout, account activation, deployed cookie/proxy behavior, webhook delivery or user credentials. No real charge, refund or payout is made by these tests.

The same browser harness covers Free/Paid edits, free creation, price validation, free labels/access, stale paywall recovery and unassigned denial at 320px in light/dark themes. For a focused rerun, set `PAYMENT_BROWSER_FOCUS=free`; the default also runs all previous test/live payment scenarios.

Browser conversion remains paused in its separate recoverable stash; no converter dependency, worker, assets, source bundle or helper is part of this release. MP4-only direct private R2 upload remains the published behavior.
